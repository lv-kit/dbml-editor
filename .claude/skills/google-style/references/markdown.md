# Markdown — Google Markdown Style Guide

適用範囲: **人間向けの文書のみ**。README、`docs/`、設計メモ、PR 本文、issue 本文が対象。`CLAUDE.md` `AGENTS.md` `rules/*.md` `SKILL.md` などエージェント向けの指示ファイルには適用しない（それらは読ませるための最適化が別にあり、既存の書き方を維持する）。

## 文書の骨格

- 見出しは ATX 形式（`#`）で書く。下線形式（`===` / `---`）は使わない
- H1 は文書の先頭に1つだけ。以降は階層を飛ばさずに下げる
- 見出しの前後に空行を1行入れる
- 長い文書には目次を置く。短い文書には不要
- ファイル名は小文字とハイフン（`getting-started.md`）。スペースとアンダースコアを使わない
- 文書は「誰が読むか」を1段落目で分かるように書き出す

## 行の折り返し

- 英文は80桁で折り返してよい。**日本語の本文は折り返さず、1段落を1行で書く**（禁則処理と差分の読みやすさのため）
- 表・長い URL・コードブロックは折り返さない
- 1文ごとに改行する方式を採るなら、文書内で一貫させる

## リンク

- リンクテキストは、リンク先が何かを説明する語にする。「こちら」「ここ」「詳細」を単独で使わない
- インラインリンク `[text](url)` を基本にする。同じ URL を何度も使うときだけ参照リンクを使う
- 相対パスでリポジトリ内のファイルを指す。絶対 URL でリポジトリ内を指さない
- URL を裸で貼らない。説明のある文にする

## リストとコード

- 箇条書きは `-`、番号付きは `1.` を使う（自動採番に任せて全部 `1.` でもよい）
- ネストのインデントは、親のマーカーの直後の文字位置に揃える
- リスト項目が複数段落になるなら、後続段落も同じ幅でインデントする
- コードブロックには必ず言語を指定する（```` ```bash ````, ```` ```python ````）
- インラインコードは、コマンド名・ファイル名・識別子に使う。強調の代わりに使わない
- 4スペースインデントによるコードブロックは使わない。フェンスを使う

## 表と強調

- 表は列が3つ以下で内容が短いときに使う。それを超えるならリストか小見出しに分ける
- 表の区切り行は必ず入れる。列幅を揃える整形は必須ではない
- 強調は `**` と `_` を使い分けず、太字は `**`、斜体は `_` に統一する
- 見出しの代わりに太字を使わない。構造は見出しで表す

## 書きぶり

- 1文を短くする。1文に主張を1つだけ入れる
- 手順は番号付きリストにし、1ステップ1操作にする
- 前提条件・環境・実行するコマンドを省略しない。読者が同じ結果を再現できる粒度で書く
- 更新されない情報（担当者名、日付、バージョン番号）を本文に埋め込まない。必要なら1箇所にまとめる
- TODO は `<!-- TODO: <文脈> - <やること> -->` で書き、本文に残さない
