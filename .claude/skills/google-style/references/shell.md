# Shell — Google Shell Style Guide

適用範囲: `.sh` `.bash` と shebang が bash のスクリプト。インデント幅と行長は shfmt / editorconfig の設定に従い、ここでは扱わない。

## いつシェルを使うか

- シェルは「他のユーティリティを繋ぐ」用途に限る。単純なラッパやビルド補助が対象
- 100行を超えたら、または非自明な制御フローが必要になったら、Python など構造化された言語への書き換えを検討する
- 実行ファイルは拡張子なし、ライブラリは `.sh` 付きで実行権限を付けない

## ファイルの骨格

- shebang は `#!/bin/bash`。オプションは `set` で明示する
- 先頭にファイルの目的を説明するコメントブロックを置く
- 定数と環境変数は先頭にまとめ、`readonly` を付ける
- 関数定義より下に処理を書かない。処理は `main` にまとめ、ファイル末尾で `main "$@"` を呼ぶ
- `set -e` の挙動（パイプやサブシェルでの例外）を理解した上で使う。頼り切らず戻り値も確認する

## 命名

- 関数名 / 変数名: `lower_with_under`。関数のワードセパレータは `::` も可（`mypackage::my_func`）
- 定数と環境変数: `UPPER_WITH_UNDER`。定義したら `readonly` か `export` を付ける
- ループ変数は反復対象と同じ語幹にする（`for zone in "${zones[@]}"`）
- 関数定義に `function` キーワードは使わず、`my_func() {` の形で書く

## クォートと展開

- 変数展開は常にクォートする（`"${var}"`）。ブレースを付けて境界を明示する
- 単語分割・グロブが必要な場面以外でクォートを外さない
- `"$@"` を使う。`$*` は使わない
- 配列は配列として扱う。スペース区切りの文字列でリストを表現しない
- コマンド置換は `$(...)`。バッククォートは使わない
- 数値の比較は `(( ... ))`、文字列とファイルのテストは `[[ ... ]]`。`[ ... ]` と `test` は使わない
- 空文字判定は `[[ -z "${var}" ]]` / `[[ -n "${var}" ]]` を使う

## 関数と変数

- ローカル変数は `local` で宣言する
- `local var="$(cmd)"` と1行で書かない。`local var` と代入を分け、コマンドの戻り値を失わないようにする
- 関数は入力を引数で受け、結果は標準出力に書く。グローバル変数への書き込みで結果を返さない
- グローバル変数は最小限にし、使うなら先頭で宣言する

## エラー処理

- エラーメッセージは STDERR に出す。通常の出力と混ぜない
- 重要なコマンドは戻り値を確認する。`if ! cmd; then` か `cmd || return 1` の形で扱う
- パイプラインの途中の失敗を見たいときは `PIPESTATUS` を確認する
- 失敗時は非ゼロで終了する。エラーを握り潰さない

```bash
err() {
  echo "$(date +'%Y-%m-%dT%H:%M:%S%z'): $*" >&2
}

if ! do_something; then
  err "Unable to do_something"
  exit 1
fi
```

## その他

- `eval` は使わない
- `cd` はサブシェル `( cd "${dir}" && ... )` の中で行うか、失敗を確認する（`cd "${dir}" || exit 1`）
- `ls` の出力をパースしない。glob か `find` を使う
- `sed -i` のような破壊的操作の前に、対象を確認する
- SUID / SGID は使わない。権限昇格が要るなら `sudo` を明示的に呼ぶ
