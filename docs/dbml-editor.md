# DBML エディタ仕様（両アプリ共通）

`web/` と `dbml-studio/` で同一の仕様。実装は各アプリに並存する（`src/lib/components/DbmlCodeEditor.svelte` / `DbmlDiagram.svelte` / `dbml-diagram-parser.ts` / `dbml-diagram-layout.ts`）。

## 状態モデル

**DBML テキストが唯一の状態**。ダイアグラム側の操作（リレーション作成、削除）はすべて DBML テキストを書き換え、その結果を再パースして描画に反映する。ダイアグラム専用の中間状態は持たない。

例外は **テーブルの表示座標** のみ。ドラッグで移動した座標はコンポーネント内の状態として保持し、DBML には書き戻さない（再読み込みで既定のグリッド配置に戻る）。

画面構成は左右 50/50 の分割。左がコードエディタ、右がダイアグラム。どちらの編集も相手側に即時反映される。

## コードエディタ

CodeMirror 6。有効な拡張:

- 行番号、アクティブ行ハイライト（本文・ガター）
- 選択描画、矩形選択
- 入力時インデント、括弧対応表示、折りたたみガター
- 編集履歴（undo/redo）
- 選択語のハイライト、オートコンプリート
- SQL 言語モードによるシンタックスハイライト（DBML 専用モードは未使用）
- キーマップ: default / history / search / completion、Tab でのインデント（`indentWithTab`）
- 高さは 100%、スクロールは `.cm-scroller` が担当

テーマ:

| アプリ | 挙動 |
|---|---|
| `web/` | `oneDark` を常時適用（ダークモード連動なし） |
| `dbml-studio/` | `Compartment` で切り替え。`darkMode` が真なら `oneDark`、偽なら既定テーマ |

外部から `value` が変わった場合、エディタ内容と異なるときのみ文書全体を差し替える。エディタ内の編集由来の更新はループしないようフラグで抑止する。

## 解析

- パーサ: `@dbml/core` の `Parser`、フォーマットは `dbmlv2`
- 全スキーマの全テーブル・全 Ref を走査する
- テーブルから取得する情報: テーブル名、テーブル note、カラム（名前、型名、主キーか、note）
- Ref から取得する情報: 両端のテーブル名・先頭カラム名・リレーション種別。**エンドポイントが2つ未満の Ref は無視する**
- テーブルのヘッダー色は定義順に12色を循環して割り当てる（`#3498db`, `#2ecc71`, `#e74c3c`, `#f39c12`, `#9b59b6`, `#1abc9c`, `#e67e22`, `#2980b9`, `#27ae60`, `#c0392b`, `#d35400`, `#8e44ad`）

### パースエラー時の扱い（`keepLastValidDiagram`）

| 状況 | 表示 |
|---|---|
| パース成功 | ダイアグラムを更新し、有効な結果として記憶する |
| パース失敗、かつ記憶している有効な結果がある | **直前の有効なダイアグラムを描画し続け**、右上に警告カード（`data-testid="diagram-parse-warning"`、見出しは `Parse error` / ローカライズ済み文言、本文は最大3行）を出す |
| パース失敗、かつ有効な結果がない | 中央に見出し（`Diagram` / ローカライズ済み）とエラーメッセージを表示 |
| テーブル0件（エラーなし） | `DBMLを入力するとダイアグラムが表示されます`（ローカライズ済み） |

エラーメッセージは `Error` の `message`、`message` を持つオブジェクトの当該値、いずれでもなければ `Parse error`。

## レイアウト（`dbml-diagram-layout.ts`）

| 定数 | 値 |
|---|---|
| テーブル幅 | 220 |
| ヘッダー高 | 32 |
| 行高 | 26 |
| テーブル下パディング | 8 |
| 列間ギャップ / 行間ギャップ | 60 / 40 |
| 列数 | 4 |
| 描画開始座標 | (20, 20) |

- テーブル高 = ヘッダー高 + カラム数 × 行高 + パディング
- 既定配置は定義順に4列のグリッド。各列は「その列で最も下にある要素の下端 + 行間ギャップ」に次のテーブルを積む
- note を持つテーブルは、占有高さに note 分（上余白8 + note ヘッダー28 + 行数 × 16）を加算する。note の行数は **30文字超で2行、それ以下は1行** として概算する
- ドラッグで座標を上書きしたテーブルは、その X 座標から所属列を推定して積み上げ計算に反映する（列インデックスは 0〜3 にクランプ）
- SVG の内容サイズは最小 800×600、テーブルの右端・下端 +40 まで拡張する

## リレーション線

- テーブル同士の位置関係に応じて接続辺を選ぶ: 送り元が受け先より完全に左なら「右辺→左辺」、完全に右なら「左辺→右辺」、重なる場合は「右辺→右辺」
- 制御点オフセットは横距離の 40%、ただし最小 30 の3次ベジェ曲線
- カラムの縦位置は「テーブル上端 + ヘッダー高 + 行インデックス × 行高 + 行高/2」。該当カラムが見つからない場合はヘッダー直下

## ダイアグラム操作

| 操作 | 入力 |
|---|---|
| テーブル移動 | テーブルヘッダーを左クリック + ドラッグ |
| カラム接続（Ref 作成） | カラム行を左クリック + 別カラムへドラッグ |
| キャンバス移動（パン） | 中クリックドラッグ、または Shift + 左クリックドラッグ、またはホイール（縦横スクロール） |
| ズーム | Ctrl / Cmd + ホイール（カーソル位置を基準に 1.1 倍 / 0.9 倍） |
| 選択 | テーブルヘッダー / カラム行 / リレーション線を左クリック |
| 選択解除 | 空白部分を左クリック、Escape、コンテナ外のクリック |
| 削除 | 選択状態で Delete または Backspace |

この一覧は Help（`HelpTooltip`）にも同内容が表示される。

### クリックとドラッグの判別

マウス移動距離が **5px（`DRAG_THRESHOLD`）** 未満のまま離した場合はクリック（選択）、超えた場合はドラッグ（移動 / 接続）として扱う。`mouseup` は `window` で捕捉するため、SVG 要素外で離しても確定する。マウスがコンテナから出た場合はパン・ドラッグ・接続をすべて中断する。

キーボードイベントは `window` の **キャプチャフェーズ** で受け取る。これはダイアグラム選択中の Delete / Backspace を CodeMirror より先に処理するため。

### Ref の作成

カラムからカラムへドラッグして離すと、離した位置のカラムを判定し、送り元と異なる場合に DBML 末尾へ次の行を追記する。

```
Ref: <fromTable>.<fromField> > <toTable>.<toField>
```

### 削除の書き換え規則

| 選択種別 | 書き換え内容 |
|---|---|
| リレーション | ① `Ref` で始まり両端の `table.field` を含む行を削除。見つからなければ ② カラム行のインライン `[ref: > table.field]` を除去（前後のカンマを整理し、`[]` だけになった括弧も削除） |
| テーブル | `Table <name> {` から対応する `}` までのブロックを削除し、さらに `<name>.` を含む `Ref` 行を削除。保持していた座標も破棄する |
| カラム | 対象テーブル内の該当カラム行を削除し、`<table>.<field>` を含む `Ref` 行を削除 |

いずれの場合も後処理（`cleanupDbml`）で **連続する空行を1行に圧縮し、末尾の空行を除去して改行1つで終える**。

テーブル・カラムの検出は行頭の `Table <名前> {` とブレース深度の追跡による字句処理で、`@dbml/core` の AST は使っていない。

### カラム note のツールチップ

note を持つカラムにホバーすると、テーブル右外（テーブル右端 + 8px、カラムの縦中央）にツールチップを表示する。幅 240、テーブル名・カラム名・型・note を含み、note は **1行26文字・最大2行** に折り返して超過分を省略記号で切る。ツールチップの配色はライト / ダーク共通の固定色。

## 配色とダークモード

- `darkMode` prop（既定 `false`）でキャンバス背景、テーブル背景・枠線、リレーション線、行区切り、カラム名、型名、note、空状態テキストの色を切り替える
- 主キーの色（`#f59e0b`）と note のドット（`#fbbf24`）は共通
- `web/` はエディタ画面から `darkMode` を渡していないため常にライト配色（[known-gaps.md](known-gaps.md)）
- `dbml-studio/` はテーマ設定に連動する。ダーク時の具体色は web 版と若干異なる

## i18n

- `dbml-studio/` はダイアグラム内の文言（`Parse error` / `Diagram` / 空状態）を `locale` prop 経由でローカライズする
- `web/` は英語・日本語の固定文言（Paraglide は導入済みだが UI 文言には未適用）

## 検証（`dbml-validator.ts`）

`validateDbml(content)` は `{ valid, error }` を返す純粋関数。

- 内容が空（trim 後）: `valid: false`、`DBMLの内容が空です`（`dbml-studio/` は第2引数でメッセージを差し替え可能・既定は同文言）
- パース成功: `valid: true`、`error: null`
- パース失敗: `valid: false`、`error` は例外の `message`、`Error` でなければ `Unknown parse error`

利用箇所:

- `web/`: ローカルファイル上書きの可否判定のみ
- `dbml-studio/`: 常時検証し、ヘッダーの「DBMLエラー」バッジと本文上部のエラーバナーに反映
