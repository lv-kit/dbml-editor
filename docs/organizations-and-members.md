# 組織とメンバー管理

対象は `web/` のみ。

## データモデル上の制約

- ユーザーの組織所属は `user.organization_id` の **単一所属**。多対多の中間テーブルはない
- ロールは `user.role` に文字列で保持する（既定値 `'member'`）
- 組織とユーザーの削除は **論理削除**（`deleted_at` を設定）
- したがって「組織一覧」は実質「自分が所属する1組織」の表示になる

## ロール

| ロール | 説明 |
|---|---|
| `owner` | 組織の所有者。組織削除が可能 |
| `admin` | 組織管理者 |
| `member` | 一般メンバー |

有効値の検証は `validateMemberRole()`（`web/src/lib/members.ts`）。上記3つ以外は拒否する。

## 権限マトリクス

判定関数はすべて `web/src/lib/members.ts` の純粋関数。`member` はいずれの管理操作も不可（`canManageMembers()` が `false`）。

### メンバー管理画面へのアクセス（`canManageMembers`）

| 実行者 | 可否 |
|---|---|
| `owner` | ○ |
| `admin` | ○ |
| `member` | × |

### ロール変更（`canChangeRole` / `canEditMemberRole`）

| 実行者 | 対象 `owner` | 対象 `admin` | 対象 `member` |
|---|---|---|---|
| `owner` | ○ | ○ | ○ |
| `admin` | × | × | ○（`owner` への昇格は不可） |
| `member` | × | × | × |

### ロールの付与（`canAssignRole`）

| 実行者 | 付与できるロール |
|---|---|
| `owner` | `owner` / `admin` / `member` |
| `admin` | `admin` / `member`（`owner` は不可） |
| `member` | なし |

### メンバー削除（`canRemoveMember`）

| 実行者 | 対象 `owner` | 対象 `admin` | 対象 `member` |
|---|---|---|---|
| `owner` | ×（他の owner は削除不可） | ○ | ○ |
| `admin` | × | × | ○ |
| `member` | × | × | × |

### 組織の管理者追加・組織削除（`web/src/lib/server/services/organization.ts`）

| 操作 | `owner` | `admin` | `member` |
|---|---|---|---|
| 管理者追加（`canAddAdmin`） | ○ | ○ | × |
| 組織削除（`canDeleteOrganization`） | ○ | × | × |

## メールアドレスの扱い

- 検証は `validateEmail()`: `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`（trim 後）
- 保存・照合はすべて `trim().toLowerCase()` で正規化する
- DB 側の照合は `lower(user.email) = <正規化済み>` で行い、大文字小文字の差による重複登録を防ぐ

## 画面と操作

### `/organizations`（組織一覧）

- 未認証は `/login?returnTo=<現在パス>`、ユーザー未登録は `/signup` へ
- 自分の `organization_id` に対応する生存組織のみを表示（未所属なら空一覧）
- 各行から「メンバー管理」（`/organizations/<slug>/members`）へ遷移
- 「組織を作成」から `/organizations/new` へ

### `/organizations/new`（組織作成）

- 検証は `/signup/organization` と同一（`name` 必須、`slug` は `/^[a-z0-9-]+$/`）
- **トランザクションで** 組織を作成し、同時に実行ユーザーの `organization_id` を新組織に、`role` を `owner` に更新する。どちらかが失敗すればロールバックして `500 組織の作成に失敗しました`
- 成功時は `/organizations` へ

### `/organizations/[id]`（組織詳細・ID 指定）

- `id` が正の整数でない、または組織が存在しない場合は `/organizations` へ
- **実行ユーザーの `organization_id` が対象組織と一致しない場合は `/organizations` へリダイレクト**（他組織の閲覧不可）
- メンバー一覧（名前・メール・ロール）を表示

アクション:

| アクション | 入力 | 振る舞い |
|---|---|---|
| `addAdmin` | `email` | 対象ユーザーのロールを `admin` にし、`organization_id` を対象組織に設定 |
| `delete` | — | 組織を論理削除 |

`addAdmin` の拒否条件とメッセージ:

| 条件 | メッセージ |
|---|---|
| 組織 ID が不正 | `無効な組織IDです`(400) |
| 未認証 | `認証が必要です`(401) |
| `email` 未入力 | `メールアドレスを入力してください`(400) |
| 組織が存在しない・削除済み | `組織が見つかりません` |
| 実行者が対象組織のメンバーでない | `権限がありません` |
| 実行者が `member` | `組織管理者を追加する権限がありません` |
| 対象 email のユーザーが存在しない | `指定されたメールアドレスのユーザーが見つかりません` |
| 対象が自分自身 | `自分自身のロールは変更できません` |
| 対象が別組織に所属している | `このユーザーは別の組織に所属しています` |
| 更新が0件 | `ユーザーの更新に失敗しました` |

`delete` の拒否条件とメッセージ:

| 条件 | メッセージ |
|---|---|
| 組織 ID が不正 | `無効な組織IDです`(400) |
| 未認証 | `認証が必要です`(401) |
| 組織が存在しない・削除済み | `組織が見つかりません` |
| 実行者が対象組織のメンバーでない | `権限がありません` |
| 実行者が `owner` でない | `組織を削除する権限がありません` |

削除成功時の副作用: **組織所属ユーザー全員のプロジェクトを論理削除した後、組織を論理削除する**。ユーザー行自体は削除しない。完了後 `/organizations` へリダイレクト。

### `/organizations/[slug]/members`（メンバー管理・slug 指定）

- 未認証は `/login?returnTo=<現在パス>`
- 組織が見つからない場合は `error: '組織が見つかりません'` を含むデータを返す（リダイレクトしない）
- **対象組織に所属する生存ユーザーとして解決できない場合は `403 この組織へのアクセス権がありません`**
- メンバー一覧をテーブル表示。ロールは日本語ラベル（オーナー / 管理者 / メンバー）で表示する

アクション:

| アクション | 入力 | 振る舞い |
|---|---|---|
| `add` | `name`, `email`, `role` | 対象組織に新規ユーザー行を作成（`user_type = 'corporate'`、認証プロバイダ情報なし） |
| `updateRole` | `targetUserId`, `role` | 対象メンバーのロールを更新 |
| `remove` | `targetUserId` | 対象メンバーを論理削除（`deleted_at` を設定） |

共通の拒否条件:

| 条件 | 応答 |
|---|---|
| 未認証 | `401 認証が必要です` |
| 組織が存在しない | `404 組織が見つかりません` |
| 実行者が対象組織のメンバーでない | `403 メンバーを管理する権限がありません`（`add`）/ `403 権限がありません`（`updateRole` / `remove`） |
| `targetUserId` 欠落 | `400 パラメータが不足しています` |
| `targetUserId` が正の整数でない | `400 無効なユーザーIDです` |
| 対象ユーザーが同一組織に存在しない | `404 ユーザーが見つかりません` |

`add` 固有:

- `name` 必須: `400 名前を入力してください`
- `email` は `validateEmail()` を満たすこと: `400 有効なメールアドレスを入力してください`
- `role` が有効値でない場合は `member` として扱う
- 付与権限がない場合: `403 この権限を付与する権限がありません`
- email 重複（事前チェック、または PostgreSQL の一意制約違反 `23505`）: `409 このメールアドレスは既に登録されています`
- その他の失敗: `500 メンバーの追加に失敗しました`

`updateRole` 固有:

- `role` が有効値でない: `400 無効な権限です`
- `canChangeRole` と `canAssignRole` の **両方** を満たさなければ `403 権限を変更する権限がありません`
- 更新0件: `404 ユーザーが見つかりません` / 例外: `500 権限の変更に失敗しました`

`remove` 固有:

- `canRemoveMember` を満たさない場合: `403 メンバーを削除する権限がありません`
- 更新0件: `404 ユーザーが見つかりません` / 例外: `500 メンバーの削除に失敗しました`

## 組織詳細の2系統について

`/organizations/[id]`（管理者追加・組織削除）と `/organizations/[slug]/members`（メンバー CRUD）が並存し、機能が一部重複している。一覧画面からは `slug` 系のみリンクされている。整理は未実施（[known-gaps.md](known-gaps.md)）。
