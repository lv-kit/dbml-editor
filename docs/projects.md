# プロジェクト管理（web/）

プロジェクトは DBML 文書1つに対応する保存単位。`dbml-studio/` にプロジェクト概念はなく、ファイル単位で扱う。

## 所有と可視性

- プロジェクトは **作成したユーザー個人の所有**（`project.user_id`）。組織単位の共有はしない
- 一覧・閲覧・保存のすべてで所有者一致を検証する
- 削除は論理削除（`deleted_at`）。UI からのプロジェクト削除操作は現状なく、組織削除の副作用としてのみ設定される

## `/projects`（一覧）

- 未認証は `/login`、ユーザー未登録は `/signup` へ
- 自分の生存プロジェクトを `created_at` 昇順で表示
- 0件のときは空状態と「最初のプロジェクトを作成」を表示
- ヘッダーに `{ユーザー名}さんのプロジェクト` を表示

### `create` アクション

| 条件 | 応答 |
|---|---|
| 未認証 | `401 認証が必要です` |
| セッションの email に対応するユーザーがいない | `401 ユーザーが見つかりません` |
| `name` が空 | `400 プロジェクト名を入力してください` |

成功時は `dbml_content` を空文字で作成し、`/projects/<id>` へリダイレクトする。

## `/projects/[id]`（エディタ）

### ロード時の検証

| 条件 | 振る舞い |
|---|---|
| 未認証 | → `/login` |
| `id` が正の整数でない | → `/projects` |
| ユーザー未登録 | → `/signup` |
| プロジェクトが存在しない・削除済み | → `/projects` |
| **プロジェクトの所有者が自分でない** | → `/projects` |

### 開始画面（`dbml_content` が空の場合）

保存済み DBML が無いときは編集画面の前に選択画面を出す。

| 選択肢 | 振る舞い |
|---|---|
| 新規作成 | プロジェクト名をコメントに含むテンプレートを投入（`Table example { id integer [primary key] / name varchar / created_at timestamp }`） |
| ファイル選択 | ローカルの `.dbml` を読み込む |

どちらも `role="button"` の要素で、Enter / Space キーでも起動できる（`$lib/keyboard.ts` の `handlePseudoButtonKeydown` / `handlePseudoButtonKeyup`）。

`dbml_content` が既にある場合はこの画面をスキップして編集画面を表示する。

### 編集画面

- ヘッダー: プロジェクト一覧へのリンク、プロジェクト名、未保存バッジ、操作ボタン群、Help
- 本体: 左にコードエディタ、右にダイアグラム（各 50%）。編集仕様は [dbml-editor.md](dbml-editor.md)
- **未保存判定**: 現在の内容が最後に保存した内容と異なるとき「未保存」バッジを表示

| ボタン | 表示条件 | 有効条件 | 振る舞い |
|---|---|---|---|
| 保存 | 常時 | 未保存の変更があり、保存中でない | `POST /projects/<id>?/save` を `fetch` で送信。成功時に保存済み内容を更新（`保存中...` を表示） |
| ファイル上書き | ローカルファイルハンドルを保持しているとき | DBML が妥当で、上書き中でない | File System Access API でハンドル先を上書き |
| ダウンロード | 常時 | 常時 | `{プロジェクト名}.dbml` として `text/plain` の Blob をダウンロード |

DBML の妥当性検証（`validateDbml`）は **ローカルファイルハンドルを保持しているときのみ** 行う。ハンドルが無い場合は常に妥当として扱い、ボタンの `title` / `aria-label` にエラー内容を出す。

上書き失敗時は `ファイル上書きに失敗しました: {メッセージ}` を `role="alert"` のバナーで表示し、閉じるボタンで消せる。

### `save` アクション

| 条件 | 応答 |
|---|---|
| 未認証 | `401 認証が必要です` |
| `id` が正の整数でない | `400 無効なプロジェクトIDです` |
| ユーザー未登録 | `401 ユーザーが見つかりません` |
| `dbmlContent` が文字列でない | `400 無効なデータです` |
| プロジェクトが存在しない、または所有者が自分でない | `403 このプロジェクトを編集する権限がありません` |
| 更新0件 | `404 プロジェクトが見つかりません` |

成功時は `dbml_content` と `updated_at` を更新し `{ success: true }` を返す。**内容の妥当性（DBML としてパースできるか）はサーバ側では検証しない** — 不正な DBML も保存できる。

## ローカルファイル連携（`web/src/lib/file-system.ts`）

- `isFileSystemAccessSupported()`: `window` に `showOpenFilePicker` があるかで判定
- 対応ブラウザ: `showOpenFilePicker` でピッカーを開く（`DBML Files` / `text/plain` の `.dbml`、単一選択）。取得したハンドルを保持し「ファイル上書き」を有効にする
- 非対応ブラウザ: 非表示の `<input type="file" accept=".dbml">` にフォールバックする。この場合ハンドルは得られないため上書きは使えない
- 未対応環境で API 依存の関数を直接呼ぶと `このブラウザではFile System Access APIがサポートされていません` を投げる
- ユーザーがピッカーをキャンセルした場合（`AbortError`）はエラー表示しない
- 書き込みは `createWritable()` → `write()` → `close()`。失敗時は `abort()` を試みたうえで元のエラーを再送出する（abort 自体の失敗は無視）

ファイルを読み込んでも「最後に保存した内容」は DB の値のまま扱うため、読み込み直後は未保存状態になる。
